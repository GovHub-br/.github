# Contribuindo com o GovHub

Este guia vale como ponto de partida para repositórios da organização que não
tenham um `CONTRIBUTING.md` próprio. Antes de contribuir, leia o `README.md` e
as instruções específicas do repositório em que vai trabalhar.

## Por onde começar

- Conheça o [roteiro de onboarding](https://gov-hub.io/documentacao/onboarding/roteiro/).
- Consulte o [guia de Git](https://gov-hub.io/documentacao/onboarding/git-workflow/) para
  orientações sobre branches, commits e Pull Requests.
- Para dúvidas e ideias ainda abertas, use as
  [Discussions do GovHub](https://github.com/orgs/GovHub-br/discussions).

## Issues e Pull Requests

1. Procure uma issue ou discussão existente antes de abrir outra. Para uma
   mudança maior, combine o escopo com os mantenedores do repositório.
2. Crie uma branch a partir da branch padrão atualizada do repositório.
3. Descreva no PR a motivação, o que mudou, como validar e a issue relacionada,
   quando houver. Siga o template e as regras locais, se existirem.
4. Execute as verificações aplicáveis ao projeto ou explique por que não se
   aplicam. Atualize a documentação se a mudança afetar o uso do projeto.
5. Não inclua credenciais, tokens ou dados sensíveis em issues, PRs, commits ou
   evidências públicas.

O [guia de contribuição da documentação](https://gov-hub.io/documentacao/CONTRIBUTING/)
traz mais detalhes sobre issues, PRs e padrões técnicos. As instruções do
repositório específico prevalecem sobre este guia geral.
